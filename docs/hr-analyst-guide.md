# HR Analyst Guide

## Sign in and choose a source

Run the application with `npm.cmd run dev`. Choose **Continue to synthetic demo** to enter with fictional sample records; no demo password is used. If organisation sign-in is configured, use the account provisioned by your administrator. The Supabase session authenticates the account, but the current dashboard still uses local demo and in-memory import data. Use **Demo Data** for synthetic records and **Imported Data** only for staged files after confirming source completeness.

Organisation accounts must have an active role assignment. The sidebar and Reports Centre are filtered by the account permissions; Management sees aggregate reports, while employee-level reports require `employee.read`. Department-scoped roles are limited to their assigned department. A missing role or unreadable permission profile denies access. These controls are in the client UI and do not replace database row-level security.

## Explore dashboards

Use the sidebar to open Executive Dashboard, Workforce, Payroll & CTC, Attendance & Leave, Performance & Increments, and Project Allocation. The month, as-of date, company, department, location, and employment type controls apply across relevant records. Imported Employee Master rows without a company can be isolated with **Not specified**. Planning records use the company filter only when their uploaded rows include a Company column. The visible employee count reflects the current selection. Tables include search and CSV download controls.

The page header reports when the synthetic dataset was loaded or when the latest successful imported stage was created; it no longer implies that local data refreshed moments ago.

Open the bell in the top bar for active imported-period readiness blockers and staged validation warnings. Each alert links to Data Quality or Data Import; the list is calculated locally and is not sent to a notification service.

Open **Data Quality** to review staged source coverage, the selected period's readiness reasons, missing employee and project references, payroll/attendance coverage, over-allocation and last successful staging time. This view contains aggregate counts only. Attendance day reconciliation is reported when all selected rows include eligible calendar days, working days, present days, weekly offs, holidays, paid and unpaid leave, and payable days. Optional Basic, HRA, allowances, employer PF/ESIC, gratuity, variable pay, incentives, arrears, and overtime amounts remain separately reported; they are never added to monthly gross or CTC. Component totals are withheld unless all in-scope employees have that component. Payroll imports let you optionally enter a source gross control total for each reporting month in the file; Data Quality compares it with valid imported gross rows from that file. A mismatch blocks payroll completeness until a replacement file reconciles. Rejected-row and warning totals summarize the latest validation batch per category; row-level errors are not persisted after staging.

Open **Employee Master** to search the roster using the same organisation filters. Status is calculated as of the selected date, so the directory can show active, exited, and not-yet-joined records. A complete Employee History stage applies department, location, designation, grade, employment type, manager, and cost-centre changes at their effective dates. Select a name to view the available workplace fields and a chronological history of confirmed workforce attributes alongside recorded join, project, and exit events. Future-dated history is not shown before its effective date. The profile intentionally omits compensation information.

On **Project Allocation**, choose Payroll monthly gross, Allocation row monthly gross, or Best available per employee. Costs are withheld when the selected basis lacks values for any filtered allocation; Payroll monthly gross also requires a confirmed payroll month. The active basis is carried into the Reports Centre project exports. Allocation headcount and FTE remain available independently of cost completeness.

Open **Recruitment**, **Contract Manpower**, or **HR Budget** to inspect imported planning rows. Demo Data intentionally shows no generated planning metrics. Recruitment time to hire uses requisition date to accepted-offer date, while time to fill uses requisition date to joining date; time to hire remains unavailable if accepted-offer dates are incomplete. Incomplete staged reporting months are labelled provisional. Increment actuals include approved effective-dated CTC changes only, converted to a monthly run-rate; pending and rejected changes are excluded. Increment budget comparison requires complete Increment and HR Budget periods. A location or employment-type filter disables the budget comparison because the budget dataset has no corresponding dimensions.

Open **Reports Centre** to preview and export the Executive MIS, headcount, joiners and exits, attrition, payroll and employee cost, department payroll, attendance, leave/LOP, performance, increments, project allocation/cost, recruitment, contract manpower, HR budget versus actual, or consolidated monthly MIS for the active filters. Excel output contains a worksheet for each report. Its Executive Summary includes the reporting period, source, active company/department/location/employment-type filters, and generation time. **Download PDF** creates a filtered PDF file directly; the executive report includes KPI cards and a monthly headcount trend. The print view remains available for browser printing. Planning rows are marked provisional when their reporting source has not been confirmed complete.

On **Performance & Increments**, open **Configure increment bands** to set three increasing percentage cutoffs. Cutoffs apply to the distribution and increment report labels for the current browser session; reloading the page resets them to 3%, 6%, and 9%. The settings are not a centrally managed company policy.

When a Recruitment source is staged, Executive Dashboard shows approved open vacancies; incomplete months are explicitly labelled provisional and the metric is hidden from users without recruitment.read. Monthly payroll YoY compares the selected month with the same month one year earlier and is shown only when both periods have complete payroll history. The Executive Dashboard reports attrition as confirmed exits divided by average opening and closing headcount. It also compares quarter-to-date and configured reporting-year-to-date closing headcount and payroll with the same elapsed months in the prior period. A comparison is labelled unavailable when required monthly history is absent or incomplete. Imported periods with incomplete source confirmation or unresolved employee/project references remain unavailable. Missing annual CTC, increments, and budgets are not inferred from gross salary.

The reporting-year start selector in the shared filter bar defaults to April (India's April–March financial year) and allows any month as the start. It changes FYTD leave calculations, completeness checks, employee leave totals, and year-to-date headcount/payroll comparisons across the dashboard and reports. Demo leave utilisation uses synthetic attendance leave days. Imported leave utilisation uses Leave records: FYTD days availed divided by opening balances plus credits, for employees active on the selected date. It is shown only when all months from the configured start are confirmed complete, employee coverage and starting balances/credits are present, and any supplied monthly balances reconcile. Otherwise the metric is unavailable and Data Quality shows why. The employee table uses imported Leave records when that dataset is staged, or the Attendance leave-taken field when no Leave dataset is staged. The selected start month applies for the current browser session and resets on refresh.

## Stage an import

Open **Data Import**, choose one of Employee Master, Employee History, Payroll, Attendance, Leave, Performance, Increment, Project Allocation, Project Master, Department Master, Location Master, Exit Records, Recruitment, Contract Manpower, or HR Budget, then select a `.csv` or `.xlsx` file. XLSX workbooks allow worksheet selection. Review the detected headers and mappings, inspect the first 20 rows, and download validation issues if needed. Synthetic CSV and XLSX templates are available for each category. Employee History requires effective-from dates, rejects overlapping periods, and applies only after its dataset is confirmed complete and employee references pass validation. Attendance accepts a reported percentage or derives it from Present Days ÷ Working Days; if both are supplied, they must agree within half a percentage point. Optional day fields are checked for impossible totals. Calendar Days means eligible days in the employee's reporting period, so adjust it for a mid-month hire or exit. LOP and leave days can be fractional. Staged Leave records feed FYTD leave totals and utilisation in Attendance & Leave when source coverage and balances pass the completeness checks. Increment records feed the Payroll and Performance views after the effective month is confirmed complete; the reported PMS increment field remains separate. Closing Leave balances are checked against opening balance + credits − availed days. Explicit Exit Records supply confirmed exit dates when Employee Master has no date; their optional Exit Type also powers the imported Workforce exit profile and average tenure-at-exit metric. Conflicts with Employee Master dates or multiple exit dates for one employee remain unresolved and lower readiness. Employees missing from an Exit Records file are not treated as exits. Department and Location datasets remain staged for review.

The Data Import quality panel summarises staged categories, valid row counts, unresolved references, and readiness reasons for the latest reporting month. The separate Data Quality page shows the selected month and source-level readiness. A month is reported ready only when all required sources and historical leave periods pass completeness checks.

The **Import history** panel records successful staging actions in the current tab using metadata only (file name, dataset, action, timestamp, row counts, and reporting months). Use **Undo staging** on the latest action to restore the prior category data or remove a newly staged category; confirm the prompt. Only the most recent successful staging action can be undone, and manually removing that category clears its undo option. The prior stage stays in tab memory only; refresh or sign out clears imports, history, and rollback state. Preview-only and rejected staging attempts are not recorded.

Imported rows remain in browser memory for the current tab. Refreshing or closing the tab clears them. Confirm a source as complete only when the file actually covers the selected roster or reporting month; imported rows do not become official records or persist to a server.

For a monthly category that already has staged rows, choose **Append new records** to add new keys. If a row collides with an existing employee, month, project, requisition, contract, or budget key, validation will stop the append. Choose **Replace periods in this file** to replace only the months represented in that file; all rejected rows must be resolved first, and the application asks for confirmation. Other staged months remain intact. Non-monthly masters replace the staged category only after a separate confirmation.
